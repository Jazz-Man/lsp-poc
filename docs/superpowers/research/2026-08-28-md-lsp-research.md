### structure

Module tree declared in main.rs:1-11: cli, completions, definitions, diagnostics, hovers, references, renames, server, structs, tracing, utils. Entry: `#[tokio::main(flavor = "current_thread")] async fn main() -> anyhow::Result<()>` → `setup_tracing(); cli::Cli::new().run().await` (main.rs:15-19).
Thin-handler mechanism, two layers:

### pitfalls

- `state.document(&url)` returns an OWNED clone of Document (framework server_state.rs:63-65 `Some(doc.clone())`); Document holds `tree_sitter_tree: Option<Tree>` by value (document.rs:40-50). Handlers always work on a snapshot — there is no mutable access to stored state from a handler. Cheap because tree-sitter trees are copy-on-write, but worth knowing: you cannot write back into the store.
- Grammar invariants are handled with `.expect("valid namespace declaration")` inside resolution code (structs/referenced_type.rs:152-153, 161-162). Legal there because zap's workspace lints only set `all=deny`, `cargo`/`pedantic=warn` (root Cargo.toml:22-32) — they do NOT gate `expect_used`. Copying this idiom verbatim would violate lsp-poc's `unwrap_used`/`expect_used` warn gates.
- Error handling is UNTYPED in the author's own server: exactly one `Err(ServerError::unknown(e))` at the formatting edge (server.rs:305); every other failure mode is expressed as `Option`/`Ok(None)`. No error.rs, no thiserror. So zap offers no precedent for lsp-poc's PocError rule — that rule has no counterpart in the canonical example.
- Position-encoding bug-risk: diagnostics' `byte_offset_to_position` computes `character: (byte_offset - line_byte) as u32` (diagnostics/mod.rs:88-97) — a UTF-8 byte offset used directly as the LSP `character`, correct only for ASCII (LSP default is UTF-16 code units). Comment at diagnostics/mod.rs:78 acknowledges the codespan byte-range mismatch only.
- Cursor-on-whitespace: `node_at_position_named` over whitespace yields an outer/no node, breaking "field: |" completions; worked around with the `completion_pos` left-stick hack (completions/mod.rs:39-106, tracing::trace on each adjustment).
- Node granularity mismatches recur in every feature: hover hits a whole declaration node and must descend `node.child(0)` + range-check the position (hovers/keywords.rs:16-31) or `find_ancestor` up to a primitive (hovers/types.rs:14); identifier nodes must be expanded to their `namespaced_type` parent before classification (hovers/types.rs:32-35, definitions/types.rs:14-17, references/types.rs:13-16, renames/types.rs:42-45); punctuation/unnamed nodes must be filtered (hovers/options.rs:22-28 via `is_punctuation_str`); root node special-cased in definition (server.rs:242-244).
- Advertises `resolve_provider: Some(true)` (server.rs:68) without implementing `completion_resolve` — silently leans on the trait's identity default; safe but easy to misread as "resolve is implemented".
- `Document::version()` and `Document::query()` exist in the framework (document.rs:113, 200 in both revs) but zap uses NEITHER (grep across src/ hits only the ServerError import) — no version-aware caching or query usage to learn from in the canonical example; also `.query()` returns `Option` (compile failure swallowed), a framework API footgun to be aware of.
- Diagnostics bypass the framework's tree entirely and re-parse `text_contents()` through a separate parser (server.rs:319-320) — the stored tree-sitter tree is apparently not sufficient (or not trusted) for the author's diagnostic needs.

### worth_copying

- Uniform per-capability free function signature — `fn hover(doc: &Document, pos: Position, node: Node) -> Option<Hover>` in every hovers/*.rs — so the trait method is always just doc/node extraction plus an `.or_else()` chain (server.rs:91-109). ### ast_role

What ast.rs is: a hand-written traversal + query layer over markdown-rs mdast (`markdown::to_mdast(buffer, &ParseOptions::gfm())`, state.rs:40,68), NOT a custom parser. Parse happens in state.rs on set_buffer/index; then parse_wiki_links mutates the tree (state.rs:43,69). Stored as MdFile{buffer, ast} per Url (state.rs:14-18).

Structure (ast.rs): AstIterator = preorder DFS with explicit stack, yields &Node (ast.rs:6-29). TraverseNode trait (ast.rs:31-57), impl for Node (ast.rs:59-268), all queries are O(n) full-tree walks, no cache/index. Query families: (a) position->node: find_linkable_for_position over Heading|Link|LinkReference|FootnoteReference (ast.rs:71-88), find_definition_for_position over Heading|Definition|FootnoteDefinition with end-column check commented out (ast.rs:89-105); both convert LSP 0-based to mdast 1-based inline. (b) identifier lookups: find_definition_for_identifier (ast.rs:147-152), find_foot_definition_for_identifier (ast.rs:154-159), find_link_references_for_identifier (ast.rs:161-168), find_footnote_references_for_identifier (ast.rs:170-177), find_def_for_link_ref (ast.rs:252-257), find_footnote_def_for_footnote_ref (ast.rs:259-267). (c) collect-alls: find_headings/find_links/find_defintions[typo,sic]/find_link_references/find_footnote_definitions/find_footnote_references/find_html_nodes (ast.rs:179-240). (d) heading-target match: find_heading_for_link / find_heading_for_link_identifier — text equality OR lowercase+space->dash slug equality (ast.rs:107-145). (e) find_next_heading: first heading starting after line N with equal depth — section-boundary primitive for hover detail and completion detail (ast.rs:242-250). Heading text extraction = first Text child (get_heading_text ast.rs:270-277; get_text_child rename.rs:233-240).

What the mdast AST gives each feature, i.e. what tree-sitter-md must replace: (1) typed enum variants with semantic fields — Heading{depth,children}, Link{url,title}, LinkReference{identifier,reference_kind}, Definition{identifier,url}, FootnoteDefinition{identifier}, FootnoteReference{identifier}, Html{value}, Text{value}. (2) unist::Position on EVERY node: 1-based line/column start+end (+byte offset), converted by range_from_position (definition.rs:79-90). (3) GFM-RESOLVED identifiers: `[^ref]` and `[^ref]: def` already carry the same normalized identifier string, so all ref<->def matching is plain String ==; the label-normalization work happens inside markdown-rs, not in md-lsp. (4) Parent/children hierarchy (Node::children(), ast.rs:21-22) so heading text and footnote text are reachable structurally. (5) Implicit "unparsed" signal: syntax mdast rejects stays as plain Text with "][" / "](" / "[^" substrings, which diagnostics.rs:73-86 exploits as broken-syntax markers. Wiki links arrive as synthetic Link nodes with hand-computed positions and title="wikilink" (links.rs:198-241) — downstream code treats them exactly like parsed links plus an is_wikilink flag.

### dprint_note

Only formatting and rangeFormatting depend on dprint (dprint_plugin_markdown::format_text + dprint-core, formatting.rs:50-62, Cargo.toml:20-21); every other feature is mdast + regex based.

### non_portable

- Workspace-wide disk index of CLOSED files (state.rs:61-90): hover/definition/references/completion/diagnostics resolve targets against buffers+ASTs of never-opened .md files loaded from disk at startup. [Inference, based on project docs] async-language-server's ServerState document store holds documents the client opened; a disk-backed index of unopened files would be new server-owned state alongside it, refreshed on didChangeWatchedFiles (md-lsp's own watcher handler is a no-op stub, server.rs:250-253 — stale-index problem left unsolved there).
- Formatting/rangeFormatting: dprint is the entire implementation (formatting.rs:50-62) and the owner excluded it — port must either drop the capability or pick a different formatter; nothing else is reusable.
- GFM resolved identifiers: md-lsp's ref<->def matching is String == on identifier fields markdown-rs already normalized (ast.rs:147-177, 252-267). [Unverified for tree-sitter-md specifics] tree-sitter grammars expose raw text spans, not normalized labels, so label matching (case folding, whitespace collapse) must be reimplemented as a normalization layer over node text — a real redesign of the ast.rs lookup family.
- Wikilink support mutates the parsed AST: parse_wiki_links injects synthetic Link nodes with hand-computed positions and a title="wikilink" sentinel into the children list (links.rs:261-287, 198-241). Tree-sitter trees are immutable parse products — wikilinks cannot become tree nodes; they need a parallel regex-scan layer (links.rs:243-259 is reusable) and every find_links/resolve_link call site must merge both sources.
- Broken-syntax diagnostics depend on the mdast quirk that invalid syntax survives as plain Text: check_links triggers on Text values containing "](", "][", "[^" (diagnostics.rs:73-86). Tree-sitter produces ERROR/MISSING nodes instead — different and arguably richer signal, but the detection condition and the byte-offset range arithmetic in find_broken_link_ref (diagnostics.rs:203-237, adds byte offsets inside Text.value to a 1-based column) do not transfer; ranges must be recomputed from tree-sitter byte columns.
- Rename range arithmetic: identifier ranges reconstructed from node start.column + identifier.len() (rename.rs:115-169) and heading-ref ranges from pos.end.column - heading_text.len() (rename.rs:265-278) — byte lengths added to character columns, ASCII-only, and already fragile. Porting must rebuild every range from actual child-node spans; tree-sitter's inline nodes (e.g. link label text) make this easier, but it is a rewrite, not a port.
- Heading anchor matching is a naive lowercase + space->dash slug (ast.rs:107-145, completion.rs:57-63), not full GitHub slugification (punctuation stripping, duplicates). Portable as-is but embeds a semantic (what a '#fragment' means) that must live somewhere in the new design since tree-sitter-md gives no anchor semantics.
- Push-vs-pull diagnostics: md-lsp implements ONLY push publishDiagnostics (server.rs:143-181, on didChange and startup; not on didOpen) and logs-and-drops textDocument/documentDiagnostic (server.rs:68-70). The host Server trait surface is `document_diagnostics` (host project structure.md), i.e. pull-shaped — the port must decide pull-only or find a push path in async-language-server; [Unverified at research time — corrected in §6.8/#1: the framework CAN emit unsolicited publishDiagnostics via `ClientSocket`; what it lacks is a trigger, since no notification hooks exist].
- Hover/completion section details require slicing raw buffer text of arbitrary indexed files (state.buffer_range_for_uri, state.rs:92-115; hover.rs:69-106; completion.rs:119-143) including sentinel EOF positions (99999/999999, hover.rs:95-97, completion.rs:138-140). Needs stored full text of unopened files (see item 1) plus a text-slicing utility — tree-sitter node text alone covers open documents only.
- FULL sync + whole-buffer reparse per change (main.rs:43, server.rs:125-133, state.rs:39-49): replaced wholesale by async-language-server's incremental tree-sitter store — an improvement, but set_buffer's reparse-and-reinject-wikilinks step has no equivalent hook in the new architecture.
- Quality gaps portable as-is but worth noting for the roadmap: workspaceSymbol ignores the query (server.rs:211-214); codeAction ignores its range/context and always offers TOC (code_actions.rs:12-31); completion trigger chars "#" and "|" are advertised but unhandled (main.rs:58-64 vs completion.rs:31-37); diagnostics not published on didOpen (server.rs:116-122); `#[allow(deprecated)]` on DocumentSymbol.deprecated (symbols.rs:24).

- Type mismatch: that crate's `language()` returns tree-sitter **0.19**'s `Language` (tree-sitter-markdown-0.7.1/bindings/rust/lib.rs:27-29), while `with_lang_grammar` wants tree-sitter **0.26.13**'s `Language` (document_matcher.rs:87). - ABI layer: LanguageFn is a newtype over `unsafe extern "C" fn() -> *const ()` (tree-sitter-language-0.1.7/src/language.rs:3-5); the 0.19-era grammar instead declares `extern "C" { fn tree_sitter_markdown() -> Language }` — a plain extern fn returning a Language struct by value (tree-sitter-markdown-0.7.1/bindings/rust/lib.rs:23-25). Wrong shape for `LanguageFn::from_raw` on two counts (signature and return type). [Unverified beyond signatures] the underlying TSLanguage layout also differs across ABI generations, and tree-sitter 0.26's `Parser::set_language` validates `abi_version()` against `MIN_COMPATIBLE_LANGUAGE_VERSION..=LANGUAGE_VERSION` (tree-sitter-0.26.13/binding_rust/lib.rs:732-742), so an old grammar would be rejected at runtime even if it linked.
- Semver ranges that let both versions coexist: tree-sitter-markdown 0.7.1 pins `tree-sitter ^0.19` (sparse index) while async-language-server requires `tree-sitter 0.26.12` (ALS Cargo.toml:35). ### risks

- Two-grammar limit (highest-impact design constraint): the framework parses each document with the matcher's single grammar (document_matcher.rs:40, document.rs:46-48, server_state.rs:133-143), so Markdown documents yield the block tree with inline content as an unparsed `inline` node; there is no injection support, no did_change hook to invalidate a side cache (server_with_state.rs:274-295), and MarkdownParser's MarkdownTree cannot be stored in Document (plain Tree, document.rs:48). Mitigation: keep early capabilities block-only; when inline is genuinely needed, side-parse the inline node's text per request keyed on Document::version() (document.rs:102) and accept re-derivation cost at POC scale; note enabling tree-sitter-md's "parser" feature adds no second tree-sitter version (its optional dep ^0.26 unifies with the framework's 0.26.12 into the single 0.26.13).
- Tree-sitter version regression (resolved at HEAD, trap remains): no conflict exists now — one tree-sitter 0.26.13 and one tree-sitter-language 0.1.7 in the graph, and rust-analyzer resolves tree_sitter_md::LANGUAGE.into() cleanly. The trap is the DIFFERENT crate tree-sitter-markdown (0.7.0/0.7.1, both 2021, hard-dep tree-sitter ^0.19) whose symptoms match the original conflict brief. Mitigation: keep tree-sitter-md 0.5.3; never wrap the 0.19 C symbol via LanguageFn::from_raw — the 0.19 binding returns Language by value (wrong signature) and the TSLanguage layout differs across ABI eras, making it UB even if cast (tree-sitter-markdown-0.7.1 bindings lib.rs:23-25 vs tree-sitter-language-0.1.7 language.rs:5,14).
- Zed pull-diagnostics behavior unverified: the fork is pull-only (document_diagnostics, server_trait.rs:250; notifications consumed internally, server_with_state.rs:274-295) while md-lsp is push-only (§6.5 correction: a push channel exists via `ClientSocket` — the missing piece is a trigger); unknown whether Zed requests textDocument/diagnostic and retries on CONTENT_MODIFIED (server_with_state.rs:71-76). Mitigation: run a live Zed experiment before scoping diagnostics; start from the fork example's advertisement (diagnostic_provider with workspace_diagnostics:false, FORK/examples/tree_sitter.rs:37-42) and zap's response envelope (zap server.rs:317-337).
- Missing trait surface caps parity: no Server methods for documentSymbol, workspaceSymbol, semantic tokens, inlay hints, or folding ranges — two md-lsp features are structurally unreachable without forking the framework. Mitigation: declare them out of scope at the brainstorm; treat any future need as a deliberate framework-fork decision, not an lsp-poc change.
- Cross-file/workspace scope: md-lsp's features resolve against a hand-built startup disk index of closed files (state.rs:61-90); the fork's substitute scan is gated on the workspace-diagnostics option (server_state.rs:241-288, server_options.rs:31-40) with unverified refresh cadence, and glob matching requires file:// URLs (untitled buffers match only via lang string, document_matcher.rs:158-165). Mitigation: keep early capabilities same-document; verify scan behavior live (what triggers refresh, staleness after external edits) before building any cross-file feature on it.
- Position/range arithmetic bugs in both reference codebases: handlers see UTF-8 positions (server_with_state.rs:21-31) yet zap computes character as a raw byte offset (zap diagnostics/mod.rs:88-97) and md-lsp adds byte lengths to character columns (rename.rs:115-169) — both ASCII-only. Mitigation: port none of that arithmetic; use tree_sitter_utils conversions exclusively and compute ranges from child-node spans.
- Stale-buffer edge: on failed incremental update the framework re-reads the file from disk and discards unsaved buffer text (server_state.rs:496-511) — can appear as intermittent 'stale hover while typing'. Mitigation: documented in advance; re-save to resync, and don't debug the feature first when it appears.

### 6.1 Lifecycle

The store is `ServerState.documents: Arc<DashMap<Url, DocumentEntry{document, origin: Open|Workspace}>>` (FORK/src/server_state.rs:37, 45-55).

- **did_open** → `handle_document_open` (313-326) → `insert_document` (118-164): matcher lookup, one grammar clone, `Parser::new` + `set_language` + `parse(&text, None)` — one synchronous full parse inside the notification handler (126-143); entry inserted, overwriting any previous state for the url (147-163). Client version + language_id, origin Open.
- **did_change** (358-514): unknown url silently ignored (362-364); origin promoted to Open (366); `doc.version = params.version` set *before* applying changes (368). Per change: `range: None` → rope replaced wholesale + full re-parse with no old tree (378-389). `range: Some` → LSP positions converted to rope char offsets (394-414); `tree.edit(InputEdit)` computed against the pre-edit rope, new-end bytes folded from the change text (419-464); then rope `try_remove`+`try_insert` (468-479). After the loop, exactly ONE incremental re-parse with the edited old tree: `parser.parse(doc.text_contents(), Some(tree))` (484-492) — note `text_contents()` re-stringifies the whole rope per did_change.
- **Failed-incremental fallback** (496-511), verified: triggers are (a) a change whose line index is out of rope bounds (394-414), or (b) rope try_remove/try_insert failure (468-479) — i.e., client ranges desynced from the buffer. The guard entry is dropped first with an explicit deadlock comment (501-505), then `std::fs::read_to_string(uri.path())` synchronously (506): ALL unsaved in-memory text — including earlier successful changes in the same notification — is discarded and replaced by disk content, re-inserted with the *client's new version preserved* (498, 507). Disk read failure → document removed (508-510). So `(url, version)` can label a state that never existed client-side.
- **did_save** (517-569): text from `params.text` (the framework forces `save.include_text: true`, server_with_state.rs:200-202) else disk; disk failure → doc removed (529-537); matcher re-resolved (543-544); full re-parse from scratch, no old tree (548-566). Version untouched (didSave carries none).
- **did_close** (328-356): kept as a Workspace snapshot (version 0, disk text) only when workspace-diagnostics enabled AND the url matches a matcher AND lies in workspace roots (339-353); otherwise removed (344-346).
- Eviction paths: close (above), refresh retain (279-283), workspace-folder removal (176-199, 295-303), disabling workspace diagnostics (233-239).

### 6.2 Snapshot semantics

`state.document(&url)` returns `entry.document.clone()` taken under a DashMap read guard (75-78). `Document: Clone` (document.rs:38-49) — Rope and Tree clones are structurally shared ("May be cloned somewhat cheaply", document.rs:21-23), matcher is `Arc`. `documents()` clones every entry (85-90). `ServerState` itself is all-Arc (34-43); each request gets `self.state.clone()` (server_with_state.rs:43) sharing the same maps. There is no mutable path into the store from a handler — snapshot-read is the only access.

Concurrency: notifications run synchronously in the main loop; requests are spawned under `ConcurrencyLayer(8)` (serve.rs:17-20, 66) — a did_change can land mid-request. The request macro re-reads the document *after* the handler and returns `ErrorCode::CONTENT_MODIFIED` if the version moved (server_with_state.rs:68-76); response re-encoding runs only on the non-stale path (78-83). The staleness check is version-only, never text.

`url + version` as identity: within one open session the client's versions strictly increase (document.rs:97-100), so it is a sound key. But (i) workspace-scanned docs are ALWAYS version 0 (inserted at server_state.rs:275; close-keep re-insert at 350) while their disk text can change → `(Url, 0)` is not unique over time; (ii) a client that restarts numbering after close/reopen can reuse `(Url, N)` with different text; (iii) the failed-incremental fallback stamps disk text with the client's new version. Good session-scoped key, not a global content identity.

### 6.3 Server-owned derived state

Bounds verified exactly: `serve` requires `S: Server + Clone` and `S: Send + Sync + 'static` (serve.rs:52-55). The Clone bound exists only because `MainLoop::new_server(builder: impl FnOnce(ClientSocket) -> S)` (ALS lib.rs:490) consumes a closure that calls `server.clone()` exactly once (serve.rs:72); `LanguageServerWithState::new` immediately wraps that clone in `Arc::new` (server_with_state.rs:135-140) and every request receives `Arc::clone(&self.server)` (42). Net: **all handlers observe the same single T instance**; the Clone impl runs once at startup and its semantics are irrelevant as long as it compiles.

Sanctioned pattern: `PocLanguageServer { inline_trees: Arc<DashMap<Url, Cached>>, .. }` — trait methods take `&self` (server_trait.rs:69-72) and return `Send` futures; DashMap satisfies both; the Arc makes the map shared across the (single) instance. This is ordinary Rust with zero framework obstacle — nothing inspects or re-clones the server after startup. What does NOT exist: any write-back into the store (Document fields are pub(crate), document.rs:40-48), and any way to construct your own store (`ServerState::new`/`with_options` are pub(crate), server_state.rs:97-105).

Precedent: none. The fork example is `struct JsonServer;` (examples/tree_sitter.rs:21); zap's is `pub struct ZapLanguageServer {}` with `new() { Self {} }` (zap server.rs:34-39); zero `DashMap|Mutex|RwLock|RefCell|Arc<` hits in zap's src. The oneshot runner reuses `LanguageServerWithState` with `ClientSocket::new_closed()` (oneshot/server.rs:19-27) — also stateless. So the Arc<DashMap> pattern compiles and works by construction, but lsp-poc would be the first user in either codebase: it is Rust-sanctioned, not framework-exemplified.

### 6.4 Notification extensibility

Prior claim verified: the fork's `LanguageServerWithState` implements `initialized`, `did_change_configuration`, `did_change_workspace_folders`, `did_open` (274-278), `did_close` (281-285), `did_change` (287-289), `did_save` (291-295) directly against ServerState; the `Server` trait has no notification methods at all.

The wiring, quoted: serve.rs:59-73 — `MainLoop::new_server(|client| { ... .service(Router::from_language_server(LanguageServerWithState::new(client, server.clone()))) })`. `Router::from_language_server` (ALS omni_trait.rs:212-238) registers a handler for EVERY method of async-lsp's generated `LanguageServer` trait — including unimplemented ones, which fall through to the default trait body. The default for notifications with `NotifyResult = ControlFlow` (ALS omni_trait.rs:21-35) is `Continue` only for `$/`-prefixed methods, `exit`, and `initialized`; everything else returns `ControlFlow::Break(Err(Error::Routing("Unhandled notification: …")))` — **the main loop terminates**. So an unexpected `workspace/didChangeWatchedFiles` or `textDocument/willSave` would not be dropped, it would kill the server. (Clients only send watched-files events to servers that registered a watcher; the fork never registers one — it registers only `workspace/didChangeConfiguration`, workspace_diagnostics.rs:276-289.)

async-lsp's Router is itself extensible — `request`/`notification`/`event` handlers plus `unhandled_request`/`unhandled_notification`/`unhandled_event` (ALS router.rs:85-201). But the fork seals it: the Router is built inside serve()'s private closure; `LanguageServerWithState` is `pub(crate)` (server_with_state.rs:129); `ServerState` constructors are `pub(crate)` (server_state.rs:97-105); and the fork re-exports neither `async_lsp` nor `Router` (fork lib.rs:3-51 re-exports only `lsp_types` from async-lsp). A downstream server cannot add its own notification handlers without abandoning `serve()` entirely — and then it has no document store, because ServerState cannot be built externally. **Sealed, plainly**: no didChange/didSave/didChangeWatchedFiles hooks, no side-cache invalidation callback, and no extension seam.

### 6.5 Client socket

`ServerState::client() -> ClientSocket` returns a clone (server_state.rs:62-64). ClientSocket's full surface (ALS lib.rs:663-717):

- `pub fn new_closed() -> Self` (676)
- `pub async fn request<R: Request>(&self, params: R::Params) -> Result<R::Result>` — round-trip request to the client (685-687)
- `pub fn notify<N: Notification>(&self, params: N::Params) -> Result<()>` — fire-and-forget notification, queued not awaited (696-698)
- `pub fn emit<E: Send + 'static>(&self, event: E) -> Result<()>` (707-709) — loopback event into the server's own router. Do not use: the fork's router registers no event handlers and the default `unhandled_event` breaks the loop (ALS router.rs:74-78).

`ClientSocket` implements `LanguageClient` (ALS omni_trait.rs:281-311), yielding typed methods for every client-side LSP message — including `publish_diagnostics` ("textDocument/publishDiagnostics", ALS omni_trait_generated.rs:96), `log_message`, `show_message`, and requests such as RegisterCapability, WorkspaceConfiguration, WorkspaceDiagnosticRefresh. R and N are generic over the lsp_types traits, so custom methods work by implementing `lsp_types::notification::Notification` on a marker type; `lsp_types` is re-exported by the fork (lib.rs:3) while `ClientSocket` is not — calling methods needs no new dep, storing the socket in a struct field requires naming it (async-lsp as direct dep).

The fork itself proves unsolicited sends from *outside* request handlers: workspace_diagnostics.rs spawns background tasks issuing `RegisterCapability` (276-289), `WorkspaceConfiguration` (302-323), and `WorkspaceDiagnosticRefresh` (338-343), spawned via `tokio::Handle::try_current` (346-350).

**Verdict on the earlier [Unverified]:** the framework CAN emit unsolicited publishDiagnostics — `state.client().notify::<lsp_types::notification::PublishDiagnostics>(params)` works from any handler or spawned task. What it does not provide is a *trigger*: with no did_change hook, nothing tells the server when to push. The channel is available; the automation is not.

### 6.6 Workspace scan

`refresh_workspace_documents` (server_state.rs:241-288) is called from exactly one place: `workspace_diagnostic_items`, the `workspace/diagnostic` request handler (workspace_diagnostics.rs:388-390). Cadence: once per client workspace/diagnostic request — no timer, no watcher. `initialized` only registers/requests configuration (221-224); `did_change_configuration` only toggles enablement (226-238).

Gates, refined: `enabled() = supported() && inner.enabled` (workspace_diagnostics.rs:72-74); the option defaults to `Enabled` (server_options.rs:31-40, `#[default]` at 36-37), but `supported()` is computed at initialize as `!Disabled && result.capabilities.diagnostic_provider.is_some()` (workspace_diagnostics.rs:103-108). **A server that does not advertise `diagnostic_provider` never scans** — lsp-poc currently advertises hover only, so the scan is inactive despite the Enabled default.

When it runs: walk roots (WorkspaceWalker, 251), match by URL glob only (`find_url`, 256), skip Open-origin docs (261-267), `std::fs::read_to_string` synchronously (274), insert with version 0, origin Workspace, language = first lang_string or lowercased matcher name (269-275); `retain` drops vanished files (279-283). Full re-walk and full re-read every invocation. Staleness: scanned entries go stale after external edits until the next workspace/diagnostic request; `did_change_watched_files` appears nowhere in the fork (zero grep hits in FORK/src) — the only async-lsp trait method exists at ALS omni_trait_generated.rs:70 and is unimplemented. `did_close` re-reads disk for workspace-matched urls (server_state.rs:349-353).

### 6.7 Inline-tree strategies

Store context: one block `Tree` per doc (6.1); inline spans surface as bare `inline` nodes. Downstream now has tree-sitter-md's `parser` feature: `MarkdownParser` (parser.rs:13), `MarkdownTree { block_tree, inline_trees, inline_indices }` (:258) with `inline_tree(parent: &Node) -> Option<&Tree>` (:286) and `parse(&mut self, text: &[u8], old_tree: Option<&MarkdownTree>) -> Option<MarkdownTree>` (:461).

**(a) Per-request parse of the one target inline node with INLINE_LANGUAGE.** Handler: snapshot → `node_at_position_named` (document.rs:163-167) → enclosing `inline` node → `doc.node_text(node)` (143-145, copies only that span) → `Parser::new().set_language(&INLINE_LANGUAGE.into())` → `parse(&text, None)`. Cost O(len of one paragraph) plus one parser construction; no block re-parse. Staleness: none beyond the snapshot itself, and CONTENT_MODIFIED discards the response if the version moved. No state, no invalidation, no eviction. Best fit for position-based features (hover over a link/emphasis).

**(b) Per-request full `MarkdownParser::parse`.** Cost O(document): re-parses the block tree (duplicating the store's own parse) plus every inline tree, each request, after copying full text (`text_bytes()`, document.rs:93-95). Buys the unified `MarkdownCursor` walk (:24) and arbitrary `inline_tree(parent)` lookups. Staleness none. Justified only for whole-document inline features; even those are covered by (a) iterated over the block tree's `inline` children at O(total inline text), skipping the redundant block re-parse.

**(c) Server-owned cache: `Arc<DashMap<Url, (i32 version, Derived)>>` on the server struct.** Read: if cached version == `doc.version()`, reuse; else parse and insert (under 8-way concurrency a double parse can race — benign for deterministic output). Incremental support exists (`MarkdownTree::edit` + `parse(old_tree)`, :258-266) but is unusable here: computing InputEdits requires change ranges, and handlers never see did_change — so every version bump means a full parse anyway. Staleness holes, both from 6.2: workspace docs are permanently version 0 (external edit + re-scan changes text at the same key → stale serve) and close/reopen can collide on `(Url, N)`. No did_close hook → no eviction; growth bounded only by documents touched. Worth it only when one request issues O(paragraphs) inline parses (references, whole-doc diagnostics).

**Recommendation: (a).** Block-first, capability-at-a-time — a heading hover needs no inline parse at all; the first inline-aware feature should parse just the target `inline` node per request. Adopt (c) only when a capability makes many inline parses per request, and then skip caching version-0 workspace docs to close the staleness hole.
