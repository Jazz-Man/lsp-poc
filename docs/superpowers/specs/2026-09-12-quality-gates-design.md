### 2. `deny.toml` — final shape

Header comment in the fork's style: "Run: make deny. Deny-level findings gate; warnings
advise. Every exception carries a reason."

- `[advisories]`: `version = 2`, `unmaintained = "all"`, `yanked = "warn"` (as today).
- `[bans]`: `multiple-versions = "deny"`, `wildcards = "deny"`, and four reasoned skips
  from our tree's triage:
  - `bitflags` version `1` — duplicate of 2.13.1: lsp-types 0.95.1 (via async-lsp 0.2.4)
    requires ^1; no lock-compatible upgrade merges them. Removed when an async-lsp
    upgrade adopts an lsp-types on bitflags 2.
  - `hashbrown` versions `0.14.5` and `0.15.5` — duplicates of 0.17.1 (indexmap):
    0.14.5 via dashmap 6.2.1 (newest dashmap release pins ^0.14.5); 0.15.5 via
    wasmparser 0.227 ← wit-bindgen 0.41 ← `zed_extension_api` 0.7.0 (the wasm side the
    fork does not have). Removed when those pins move.
  - `syn` version `2` — duplicate of 3.0.4: the syn 2 side is upstream proc-macro
    crates (arch-lint tooling, miette-derive, tracing-attributes, wit-bindgen, the
    url/icu chain); the syn 3 side is serde_derive, thiserror-impl, tokio-macros,
    clap_derive, futures-macro, lsp_macros. A major-version split cannot be merged by
    `cargo update`. Removed when syn 2 dependents release syn 3-compatible versions.
  - `windows-sys` version `0.59` — duplicate of 0.61.2: waitpid-any 0.3.0 (the newest
    release, via async-lsp 0.2.4) requires ^0.59 while rustix 1.1.4 / errno 0.3.14 (the
    same waitpid-any chain) and clap's anstream chain already sit on 0.61.2 — no
    lock-compatible upgrade merges them. Removed when a waitpid-any release allowing
    windows-sys 0.60+ lands, then `cargo update -p errno -p rustix` and delete the skip.
- `[licenses]`: `allow = ["MIT", "Apache-2.0", "Unicode-3.0", "Zlib"]`,
  `unused-allowed-license = "warn"`. Zlib confirmed exercised (zero unused warnings in
  the triage run).
- `[sources]`: `unknown-registry = "deny"`, `unknown-git = "deny"`,
  `allow-registry = ["https://github.com/rust-lang/crates.io-index"]`,
  `[sources.allow-org] github = ["Jazz-Man"]` — the fix for sources FAILED: org name,
  not `owner/repo`.
- All template boilerplate comments removed; header comment in the fork's style.

### 8. `dylint.toml` (new, root)

Same two external suites the fork adopted (owner decision 2026-09-08 upstream:
third-party style suites instead of custom lints):

- `{ git = "https://github.com/KSXGitHub/perfectionist", tag = "0.0.0-rc.22" }`
- `{ git = "https://github.com/trailofbits/dylint", tag = "v6.0.4", pattern = [...] }`
  — the `pattern` list copied verbatim from the fork's `dylint.toml`, including their
  two dropped-lint reasons
  (`non_thread_safe_call_in_test`: flags every `std::fs` call in tests, by-design fires
  for the temp-workspace test convention; `assert_eq_arg_misordering`: demands
  const-first arguments against the ecosystem's actual-first convention).

`[perfectionist] disable` mirrors the fork's three, with this repo's reasons:

- `thiserror_usage` — prescribes `derive_more` and bans thiserror; this repo's
  error-handling rule mandates thiserror (`PocError`). The suites prescribe opposite
  policies; ours wins.
- `excessive_inline_tests` — wants inline tests extracted to files; the testing
  convention this repo is adopting (steering round) mandates inline `#[cfg(test)] mod
  tests` per module.
- `single_letter_generic` — `Result<T, E>`-style generics are the ecosystem idiom;
  renaming degrades the code. (Distinct from the single-letter closure/const rules,
  which stay active.)

First real `make dylint` run builds the drivers (slow, one-time) and triages actual
fires on this codebase; new disables are added only with reasons, never to hide fires.
